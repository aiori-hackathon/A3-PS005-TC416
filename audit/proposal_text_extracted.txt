Abstract and Problem Description
Abstract
HORA Q is a prototype for detecting selected BGP origin-AS changes and  
new more-specific prefixes. It correlates observations with history,  
provenance and available RPKI context to give explainable findings. A  
cautious baseline policy keeps new or conflicting observations from being  
trusted until defined evidence criteria are met. A Post-Quantum  
Evidence Vault signs investigation records with ML-DSA for independent  
verification. A replay laboratory compares the workflow with a simple  
reference detector.
Problem Description
Origin changes and more-specifics may be malicious, accidental,  
planned or benign
Basic alerts lack history and evidence provenance
Unverified observations can undermine a local baseline
Incident records need evidence, rule versions and timestamps
Signatures must verify independently without proving an  
observation true
Problem to solve: how can a BGP monitor produce explainable anomaly findings, protect its baseline from unverified  
observations and preserve independently verifiable incident evidence?

Background
BGP lets autonomous systems exchange reachability for IP prefixes. A  
changed origin AS or a new more-specific prefix can indicate an anomaly,  
but neither alone proves malicious intent. RPKI origin validation adds  
context on whether an origin AS is authorized under available ROA data [2,  
3]; it does not establish full-route safety or intent. HORA Q treats  
observations as evidence with provenance, timestamps and limits, keeps a  
versioned baseline, and leaves conflicting or insufficient evidence visible.

Literature and RFC Review
Standards
RFC 4271 defines BGP-4 [1]. RFC 6811 (updated by RFCs 8481  
and 8893 [9, 10]) and RFC 9582 cover prefix-origin validation and  
ROAs [2, 3].
Existing Tools
BGPalerter supports unexpected-origin and more-specific alerts  
[4]. ARTEMIS is an established hijack-detection system [5].  
HORA Q claims no novelty for basic detection.
Research Risk
Research reports that crafted public observations can mislead  
certain ML-based hijack detectors [6]. HORA Q studies baseline  
contamination in controlled scenarios; it does not claim to solve  
all poisoning attacks.
HORA Q Contribution
An integrated, testable workflow: cautious baseline promotion,  
provenance-aware explanations, explicit uncertainty, ML-DSA-
signed records [7] and independent verification, evaluated  
against a reference detector.

Baseline Promotion Policy
Evaluate source provenance, freshness, historical consistency,  
corroboration and validation context. Record each decision and  
rationale; keep observations as candidates when evidence is  
insufficient or conflicting.
Post-Quantum Evidence Vault
Stores canonical records, evidence hashes, algorithm, key ID  
and verification metadata. ML-DSA protects record integrity  
relative to the key; it does not prove the observation is true or an  
attack occurred.
Safety boundary:  HORA Q does not automatically change network routes.
